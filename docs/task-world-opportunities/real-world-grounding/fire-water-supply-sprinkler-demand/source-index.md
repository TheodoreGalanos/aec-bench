# Fire Water Supply And Sprinkler Demand Source Index

## Current Chain Confidence

The chain is realistic: hydrant/water-supply evidence establishes available flow/pressure; hazard classification and sprinkler layout establish demand; piping/elevation losses consume demand; fire pump boost is required if supply is insufficient; the result is packaged for AHJ/authority review through plans, reference points, hydraulic calculations, and supporting product curves.

Publicly accessible primary standard text is limited. NFPA 13, NFPA 20, and NFPA 291 are known primary authorities, but the public landing pages expose little content through our current access path. This should be documented as a standards-access gap, not silently bypassed.

Recent source additions sharpen three distinct real-world branches: FM plan review for insurer/loss-prevention review packets, Fire Underwriters Survey for Canadian public fire-flow and hydrant recognition, and HFSC/NFPA 13D-oriented residential water-supply decisions. The FUS Water Supply Form (WS4) is now captured as a concrete blank form artifact rather than only a download-page route; it strengthens Canadian water-supply source-pack fields for hydrant coverage, flow-test attachments, engineering reports, hydraulic-model results, pressure zones, pump capacities, and dry hydrants. USEPA WNTR now materially improves the open fire-flow modelling fixture path by pairing EPANET-compatible network files with a fire-flow example/tutorial and small expected-output CSV artifacts. A focused raw-file pass pins the WNTR fixture shape further: `Net3.inp` is a 168-hour GPM/Hazen-Williams EPANET network, `fire_flow.py` uses PDD and a 4000 gpm demand at junction 197 from hours 10 to 36, and the tutorial's two expected-output CSVs each contain 39 keyed rows with six nonzero impact locations. A follow-on provenance pass pins the current `main` commit inspected on this run (`2a69d56073436c9bb5d0290ce1276d46c38b5474`, committed 2026-06-25 UTC), the latest GitHub release (`1.4.0`, published 2025-11-22 UTC), commit-pinned raw URLs, and SHA-256 hashes. A temporary `uv run --with wntr==1.4.0` reproduction against the pinned files matched both official CSV oracles exactly. FM's code-support report route now adds public, report-shaped sprinkler-demand evidence for EN 12845 and NFPA 13 code-change proposals: full-scale fire tests, storage geometry, sprinkler K-factors/pressures/flows, activation patterns, plan/elevation figures, evaluation criteria, and recommendation tables. These sources do not close the accepted-calculation or filled-form gaps, but they make the source-pack and verifier boundaries much clearer.

## Real Inputs

- Hydrant flow test: static pressure, residual pressure, flow hydrant pitot pressure, outlet diameter/coefficient, date, hydrant IDs, and network condition.
- Utility pressure/flow information or hydrant field test results: modelled residual pressures at flow steps, measured pressure hydrant, measured flow hydrant, flow increments, test equipment, and network constraints.
- Optional EPANET-style supply model: reservoir/tank/source assumptions, pipe/node topology, pumps, valves, emitter/fire-flow node, and pressure constraints.
- Optional EPANET fire-flow analysis basis: target junction, normal demand, added fire demand, required pressure, emitter coefficient if using available-flow method, and reported pressure/actual demand.
- Optional WNTR fire-flow fixture basis: selected EPANET-compatible `.inp` network, PDD demand model, target hydrant/junction list, fire-flow demand and duration, start/end time, minimum pressure, required pressure, baseline low-pressure nodes, and population or service-impact data where used. The inspected raw fixture pins a Net3 branch with GPM/Hazen-Williams units, a 4000 gpm single-node script scenario at junction 197 from hours 10 to 36, and an 8000 gpm tutorial scenario with a 2-hour start, 4-hour duration, 5 psi minimum pressure, 20 psi required pressure, and 6-to-8-inch connected-pipe hydrant filter. A benchmark source pack should carry the WNTR commit SHA, latest release context, raw file URLs, hashes, line counts, file sizes, license notices, and solver/runtime version used for reproduction.
- Canadian public fire-flow basis: effective building area, construction coefficient, occupancy/contents adjustment, sprinkler-protection adjustment, exposure charge, required residual pressure, duration, maximum-day demand, and hydrant recognition/maintenance status.
- Hazard/occupancy classification and design density/area.
- Sprinkler layout: remote area, sprinkler K-factor, spacing, elevation, node references, and piping network.
- Riser schematic: pipe sizes, fittings, valves, backflow preventer, elevation differences.
- Fire pump curve and available suction pressure.
- AHJ/owner submittal inputs: stamped drawings/calculations, water-flow request or purveyor data, water-flow test age, city-main size/dead-end/circulating status, supply elevation, backflow loss graph, water-supply graph, owner certificate, manufacturer data sheets, and accepted hydrant locations where applicable.
- FM-style property-risk review inputs: fire-protection drawings/sections, sprinkler detail drawings, material cut sheets, hydraulic calculations, actual hydrant-flow evidence, seismic bracing package where relevant, storage commodity/height/arrangement/aisle-width fields, fire-pump curves, pump-room details, and underground-main shop drawings.
- FM code-support report inputs: commodity class, storage height, ceiling height, rack or pile arrangement, aisle width, sprinkler K-factor, sprinkler spacing, operating pressure or flow, activation sequence, gas/steel temperature instrumentation, fire-spread/damage observations, and test-result acceptability.
- Residential 13D-style inputs: local authority basis, stand-alone versus multipurpose system, living-area coverage decision, riser components, household main/tap/meter size, backflow or meter losses, flow switch/alarm choice, and minimum water-duration basis.
- Regional branch inputs: NFPA 13/13R/13D basis, AS 2118.1/2118.4/2118.6 or FPAA101D/H path, building class/occupancy, residential-care status, and authority-specific acceptance route.

## Real Outputs

- Available water supply curve and design residual flow.
- Water-network fire-flow results where available: node pressures, pipe flows, pump/valve status, and limiting supply node.
- WNTR-style fire-flow fixture outputs where used: nominal versus fire-flow pressure difference, impacted junction count by hydrant/fire-flow location, impacted population or demand proxy, convergence failures, and CSV/result-table artifacts. The inspected expected-output CSVs provide a compact oracle shape: 39 keyed rows each, six nonzero impact locations, 10 total impacted junctions, and 6,398 total impacted people.
- Sprinkler demand flow and end-head pressure.
- Hydraulic calculation summary: node/pipe flows, equivalent lengths, Hazen-Williams coefficients, pressure losses, elevation losses, available pressure, operating pressure, and pressure remaining.
- Pump boost requirement and residual margin.
- Fire protection calculation/report suitable for AHJ review, including supply/demand graph, highlighted remote area, common reference point flow/pressure, matching plan-calculation reference nodes, data nameplate fields, and plan comments or acceptance caveats.
- Insurer/property-risk review package: plan-review checklist response, drawings/calculations/cut sheets, actual hydrant-flow basis, storage-occupancy note, seismic bracing note where applicable, pump-curve bundle, and review exceptions.
- FM code-support report result: standard-change rationale, test-condition summary, plan/elevation figures, sprinkler activation pattern, demand-area implication, storage-limit or sprinkler-flow/pressure recommendation, and explicit note that the report is research support rather than a project approval.
- Public fire-flow/community-risk result: required fire flow and duration, residual-pressure basis, supply adequacy/reliability note, hydrant recognition note, and sprinkler-credit explanation where applicable.
- Residential water-supply branch result: 13D/local-authority note, water-duration basis, riser/backflow/meter pressure-loss note, tap/meter implication, and stand-alone or multipurpose system decision.

## Task Implications

- The current chain is correct, but the source authority must be explicit because fire protection is code-driven. Current BSI metadata strengthens the UK/EU path; current AS 2118.1 and AS 2419.1 metadata plus South East Water guidance strengthen the Australian path; US/NFPA and detailed regional criteria still need public-view or licensed text before deterministic code-table variants.
- USFA, SFFD, Mason County, and GMU improve the public AHJ-review evidence layer. They show what a real submittal must carry, but they do not remove the need for licensed/public-view design criteria or accepted worked examples.
- NCC Specification 17 and the NSW standard strengthen the Australian branch by showing that sprinkler-system selection depends on building class, residential-care use, combined sprinkler/hydrant systems, FPAA alternatives, and certification/report pathways.
- EPANET strengthens open water-supply/fire-flow variants, but should be treated as supply-network evidence rather than sprinkler-code authority.
- WNTR now gives a concrete open fire-flow modelling fixture route with network files, procedural scripts/notebooks, and small result tables. Use it to grade supply-network consistency and scenario mutation, while keeping sprinkler hydraulic-code acceptance as a separate task-supplied or licensed criteria layer. The next benchmark step is no longer discovery of an open route or basic solver proof; it is packaging the pinned Net3/script/tutorial/CSV files with provenance, license notices, solver/runtime command, scenario metadata, and expected-output comparison rules into a task-sized source pack.
- FM code-support variants can now test whether a model reads storage-hazard reports as report-shaped evidence: extract test setup, commodity, geometry, sprinkler parameters, activation/damage results, and recommendation boundary. These variants should not treat report recommendations as a complete FM data-sheet replacement or as AHJ approval for a specific project.
- Benchmark variants should include branch decisions for hazard class, network topology, water source basis, field test versus modelled PFI basis, AHJ/owner checklist, regional/building-class path, and whether a pump is required.
- Multimodal expansion should focus on sprinkler drawings, riser schematics, hydrant test forms, water-supply graphs, plan-calculation reference-point reconciliation, and pump/backflow curves.
