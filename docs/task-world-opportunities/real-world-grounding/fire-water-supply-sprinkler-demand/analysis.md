# Fire Water Supply And Sprinkler Demand Analysis

## Real Workflow Chain

The chain is realistic:

hydrant/water-supply evidence -> available supply curve -> hazard and design criteria -> sprinkler remote-area demand -> pipe/elevation/friction losses -> pump requirement if supply is insufficient -> hydraulic calculation/report for AHJ review.

The important constraint is that this is a code/AHJ task. NFPA 13, NFPA 20, and NFPA 291 are the right authority family for the US/global-influence path, but public clause text is limited through the current access path. Current BSI metadata now gives a stronger UK/EU path through BS EN 12845:2015+A2:2026 and BS 9251:2021. Standards Australia metadata strengthens the Australian path through AS 2118.1:2017 Amd 3:2024 for automatic sprinklers and AS 2419.1:2021 for hydrant installations. Exact design criteria remain standards-controlled, so the benchmark should store the source authority and avoid silently baking copyrighted tables into tasks.

The USFA, SFFD, Mason County, and GMU sources add the missing "review packet" layer. Real sprinkler work is not just the calculation answer; it is a submittal with water-flow provenance, plan fields, hydraulic calculation sheets, reference points that agree between plans and calculations, supply/demand curves, density/design-area/hose-stream demand, and stamps or certification. This strongly supports long-horizon composite source packs where a model must inspect multiple artifacts and reconcile them.

FM adds a parallel insurer/property-risk review route. Its public project-services page treats sprinkler installations/modifications, fire pumps, suction tanks, and underground fire-water mains as projects that should go through plan review. Its checklist makes the review packet concrete: fire-protection drawings, sectional views as needed, material cut sheets, sprinkler detail drawings, hydraulic calculations, actual hydrant-flow water supply, storage occupancy details, seismic bracing evidence where relevant, fire-pump curves, pump-room details, and underground-main drawings/calculations. This is especially useful for composite tasks because it joins sprinkler hydraulics with storage hazard, seismic restraint, pump selection, and underground fire-water-main scope.

FM's technical reports supporting code change add a different kind of evidence: not project-review checklists, and not full data-sheet text, but public report-shaped research used to support FM data sheets and external standards/codes. The EN 12845 incidental-storage report ties FM Data Sheet 3-26 criteria to full-scale tests with storage geometry, 49-sprinkler operation patterns, K160/K11.2 sprinklers, operating pressure, discharge density, target-damage observations, and storage-limit recommendations. The NFPA 13 reports add storage-specific ESFR and in-rack sprinkler evidence with K-factors, ceiling/storage heights, discharge pressures or flow recommendations, activation counts, gas/steel temperature criteria, fire-spread/damage outcomes, plan/elevation figures, and recommendations for code-change tables. This materially improves the sprinkler-demand/report-artifact branch, especially for storage-hazard variants, but it still does not provide a filled hydrant-flow form, processed water-flow request, accepted project hydraulic calculation, or full FM data-sheet criterion set.

USEPA EPANET strengthens the upstream water-supply side of the chain. It gives an open, official modelling surface for municipal supply networks, hydrant/fire-flow cases, node pressures, pipe flows, pumps, valves, emitters, minor losses, and network maps. That is valuable for composite source packs, but it should be separated from sprinkler-code criteria and AHJ acceptance.

The EPANET manual/FAQ makes the fire-flow modelling variant more executable: one path adds the fire flow to a junction's normal demand and checks pressure; another estimates maximum available flow at a target pressure with an emitter coefficient and pressure-head adjustment. This lets us define a supply-network fixture without pretending that EPANET decides NFPA/EN/AS sprinkler acceptance.

USEPA WNTR strengthens that fixture path. The public WNTR repository is EPANET-compatible, includes example networks, and ships a fire-flow script/tutorial that runs pressure-dependent-demand simulations with added fire-flow demand. The simple script applies 4000 gpm fire demand at Net3 junction 197 between hours 10 and 36 and compares pressure at 24 hours. The tutorial generalizes this into hydrant candidates, minimum and required pressure thresholds, 8000 gpm fire demand, baseline low-pressure screening, per-hydrant simulations, impacted-junction counts, impacted-population estimates, and CSV outputs. Raw fixture inspection makes this more benchmark-ready: `Net3.inp` is a 496-line EPANET Example Network 3 file with 168-hour duration, GPM units, and Hazen-Williams headloss; the two fire-flow CSV outputs each contain 39 keyed rows with six nonzero locations, totaling 10 impacted junctions and 6,398 impacted people. Provenance inspection pins the current `main` snapshot to commit `2a69d56073436c9bb5d0290ce1276d46c38b5474`, latest GitHub release `1.4.0`, Revised BSD licensing for WNTR, MIT licensing for included EPANET code, and SHA-256 hashes for the five raw files. A temporary `uv run --with wntr==1.4.0` reproduction using the pinned raw files matched both official CSV outputs exactly. This is the best open route found so far for a redistributable fire-flow model fixture, but it is still a modelling and resilience-analysis artifact, not AHJ approval evidence for sprinkler hydraulic design.

FUS adds a Canadian public-fire-flow branch. The Water Supply guide evaluates public/private distribution systems for municipal fire protection, required fire flow, residual pressure, duration, maximum-day demand, storage, pumping reliability, and building-risk adjustments. It also treats automatic sprinkler protection as a credit in community/property fire-flow assessment. The hydrant bulletin adds a trust/recognition layer for public versus private hydrants and maintenance responsibility. The captured WS4 Water Supply Form turns that branch into a concrete municipal update packet: it asks for hydrant spacing/coverage, inspection and flow-test frequency, and attachments for flow-test results, hydrant maps, engineering reports, hydraulic model results for fire flow plus maximum-day demand, flow schematics, pressure zones, pump capacities, and dry hydrants. This branch is not the same as commercial sprinkler hydraulic design, but it is very useful for site fire-flow, hydrant availability, and regional public-protection tasks.

South East Water adds a useful utility procedure for the supply side: modelled PFI can be validated with a two-hydrant field test where one hydrant records pressure and another records flow. The SCI hydraulic calculation sample adds a report-shaped output: remote-area scenario, K-factor, sprinkler flows/pressures, pump pressure/flow, static/residual pressure, available/operating/remaining pressure, and pipe-run loss tables.

NCC Specification 17 and the NSW Fire Sprinkler Standard make the Australian branch more than a standards-name swap. The branch can change the applicable AS 2118 part, FPAA technical-specification eligibility, building-class path, residential-care compliance route, monitoring requirements, and whether an alternative solution needs fire-safety-engineer certification/reporting.

HFSC adds a residential NFPA 13D-oriented branch. Its public material identifies one- and two-family/manufactured-home sprinkler scope, life-safety intent, at least 10 minutes of water for the initial fire stage, local authority overlays, living-area coverage focus, stand-alone versus multipurpose layouts, riser components, backflow/meter pressure losses, and tap/meter sizing implications. This branch should be separate from NFPA 13 commercial review tasks because the protected objective, coverage assumptions, and water-supply decisions differ.

## Real Inputs

- Hydrant flow test: static pressure, residual pressure, flow hydrant, pitot pressure, outlet diameter/coefficient, test date, and network condition.
- PFI or hydrant-test procedure evidence: modelled residual pressures at flow steps, pressure hydrant, flow hydrant, test increments, equipment, and maximum permitted test flow.
- Optional water-network model: reservoir/tank/source assumptions, pipe/node topology, pumps, valves, emitter/fire-flow demand node, and pressure constraints.
- Optional EPANET fire-flow modelling basis: target junction, normal demand, added fire demand, target residual pressure, emitter coefficient if estimating available flow, pressure-head conversion, and pressure/demand outputs.
- Optional WNTR fire-flow fixture basis: EPANET-compatible network such as Net3, PDD settings, hydrant candidate rule, selected target junction, fire-flow demand, start and duration, minimum and required pressure thresholds, baseline non-zero-demand junction pressure screen, and any population or service-impact mapping. The inspected raw fixture pins a simple-script scenario at junction 197 with 4000 gpm from hours 10 to 36, plus a tutorial scenario with 8000 gpm, 2-hour start, 4-hour duration, 5 psi minimum pressure, 20 psi required pressure, and a 6-to-8-inch pipe-diameter hydrant candidate filter. Source-pack provenance should include commit `2a69d56073436c9bb5d0290ce1276d46c38b5474`, raw file URLs, file sizes, line counts, SHA-256 hashes, license notices, latest release context, and an explicit solver/runtime environment.
- Public fire-flow/community-risk basis: construction type/coefficient, effective floor area, occupancy/contents adjustment, sprinkler protection credit, exposure charge, residual pressure, duration, maximum-day demand, storage/pump reliability, and public/private hydrant recognition.
- FUS WS4 municipal water-supply update fields: province, region/county/district, municipality, water-system name/type, contact, servicing bylaw, FUS-guide use in required-fire-flow/hydrant-coverage decisions, hydrant spacing standards, dwelling/non-dwelling hydrant coverage, hydrant inspection/teardown/flow-test frequency, hydrant map status, engineering-report status, hydraulic-model status, flow-schematic status, pressure-zone count, pump count/capacity, and dry-hydrant status.
- Occupancy/hazard classification, design density/area, hose allowance, and applicable AHJ/code basis.
- Sprinkler layout, K-factor, spacing, remote area, node references, pipe network, fittings, valve/backflow losses, and elevations.
- Fire pump curve and available suction pressure where a pump is needed.
- Riser schematic, hydraulic calculation worksheets, and equipment schedules.
- AHJ source-pack evidence: stamped drawings/calculations, plan checklist fields, accepted hydrant locations where applicable, water-flow data age, purveyor or authority source, water-supply graph, hydraulic data nameplate, owner certificate, manufacturer data sheets, pump/backflow curves, and inspection/approval status.
- FM/property-risk source-pack evidence: fire-protection drawings/sections, sprinkler detail drawings, material cut sheets, actual hydrant-flow evidence, hydraulic calculations, seismic bracing proposal where applicable, storage commodity/height/arrangement/aisle width, pump curves, pump-room details, and underground-main shop drawings/calculations.
- FM code-support report evidence: standard-change target, FM data-sheet reference where applicable, commodity and storage arrangement, ceiling/storage height, aisle width, rack/pile geometry, sprinkler K-factor, spacing, flow or pressure, activation sequence, gas/steel temperature measurements, damage extent, and recommendation boundary.
- Residential 13D source-pack evidence: local authority basis, living-area coverage decisions, stand-alone or multipurpose layout, household main/tap/meter basis, riser components, flow switch/alarm basis, backflow prevention, pressure losses through meter/backflow devices, and minimum water-duration basis.
- Regional branch variables: NFPA/EN/AS/NCC/owner basis, building class, residential-care or domestic/residential path, combined sprinkler/hydrant system status, and alternative-solution certificate/report route.

## Real Outputs

- Available water supply curve.
- Water-network fire-flow/supply model results where available: node pressure, pipe flow, pump status/energy, and limiting supply node.
- WNTR-style fire-flow result tables: pressure difference between nominal and fire-flow runs, junctions falling below minimum pressure because of the fire-flow scenario, impacted-junction counts by hydrant/fire-flow location, impacted-population or demand proxy, convergence-failure flags, and CSV outputs. The inspected CSV oracle is compact enough for deterministic grading: 39 keyed rows per table, six nonzero impact locations, 10 total impacted junctions, and 6,398 total impacted people.
- Sprinkler demand point and remote-area calculation.
- Hydraulic calculation summary: node pressures, pipe flows, equivalent lengths, Hazen-Williams coefficients, losses, elevation changes, available pressure, operating pressure, remaining pressure, and end-head pressure.
- Pump boost requirement and residual margin.
- AHJ-facing calculation/report with assumptions and source basis.
- Review packet summary: supply/demand graph, highlighted remote area, density/design-area/hose-stream demand, common reference point demand, matching plan/calculation nodes, calculation exceptions, and branch-specific authority notes.
- Property-risk/insurer review summary: required drawings, cut sheets, hydraulic calculations, actual hydrant-flow evidence, storage-occupancy details, seismic bracing status, pump-curve bundle, underground-main scope, missing-document exceptions, and review-path caveats.
- FM code-support report summary: code-change context, tested storage/sprinkler configuration, plan/elevation/test-setup references, activation and damage outcome, demand-area implication, recommended storage or sprinkler-flow/pressure boundary, and caveat that this is research/report evidence rather than project approval.
- Public fire-flow/community-risk summary: required fire flow, duration, residual-pressure basis, supply adequacy and reliability, hydrant recognition/maintenance status, and any sprinkler-protection credit.
- Canadian WS4-style municipal water-supply submission: completed water-system fields, hydrant-coverage statements, flow-test/hydrant-map/engineering-report/model/schematic attachment register, pressure-zone and pump-capacity summary, dry-hydrant note, and unresolved attachment exceptions.
- Residential water-supply memo: 13D/local-code basis, water-duration basis, system type, riser/backflow/meter pressure-loss impacts, tap/meter recommendation, and local authority exceptions.

## Harness Implications

- The verifier should check whether the model constructs the water-supply curve and demand point consistently, not only whether it computes one pressure loss.
- Strong failure modes include wrong hydrant-test curve extrapolation, wrong hazard basis, using pipe lengths without fittings/elevation, missing hose allowance, and recommending a pump without checking suction/residual constraints.
- Because standard tables are gated, some variants should use task-provided criteria instead of requiring memorized code values.
- A UK/EU branch can now explicitly distinguish fixed sprinkler systems under EN 12845 from domestic/residential sprinkler systems under BS 9251, while still supplying task-local design criteria for deterministic grading.
- An Australia branch can now distinguish sprinkler-system authority under AS 2118.1 from hydrant-installation and field-test authority under AS 2419.1, while still supplying task-local design criteria for deterministic grading.
- NCC/NSW variants should test classification and approval-path reasoning separately from the hydraulic math: for example AS 2118.1 versus AS 2118.4 versus AS 2118.6, FPAA101D/H eligibility, or deemed-to-satisfy versus alternative-solution evidence.
- EPANET-backed variants should grade water-network consistency separately from sprinkler hydraulic-code compliance. Otherwise the benchmark risks conflating municipal supply modelling with sprinkler design approval.
- WNTR-backed variants can now use redistributable network files and result-table artifacts to grade scenario construction: whether the model picks the right network, applies PDD and fire-flow demand at the right nodes/times, compares against baseline pressure, handles convergence failures, and reports impacted junctions or population. A `wntr_fire_flow_oracle_packet` should include raw file provenance, the Net3 options that affect hydraulics, scenario parameters, file hashes, license notices, the `uv run --with wntr==1.4.0` reproduction command, and exact CSV comparison rules. These variants should be labelled as water-network/fire-flow modelling tasks, not accepted sprinkler-design tasks.
- AHJ-submittal variants can grade consistency across artifacts: water-flow test age, water-main data, supply graph, plan reference nodes, remote-area highlighting, hydraulic calculation sheets, and pump/backflow curves.
- FM/property-risk variants can grade whether the packet includes actual hydrant-flow evidence, drawings/sections, hydraulic calculations, storage details, seismic bracing where applicable, pump curves, and underground-main scope without making FM data-sheet criteria implicit.
- FM code-support report variants can grade extraction and reasoning over public storage-sprinkler reports: whether the model distinguishes test conditions from recommendations, extracts K-factor/pressure/flow/spacing/geometry/activation outcomes, and avoids using code-change research as if it were a complete AHJ-approved hydraulic calculation or full licensed standard.
- Canadian public-fire-flow variants can grade required-fire-flow reasoning, residual-pressure/duration, maximum-day demand, water-supply reliability, public/private hydrant recognition, and sprinkler-credit reasoning separately from sprinkler hydraulic-code compliance.
- Canadian WS4 variants can grade completeness and consistency of a municipal water-supply update packet: whether required attachments are present when the form answers yes, whether flow-test/model results match the stated water-system and pressure-zone context, and whether hydrant coverage/maintenance fields are reconciled with hydrant maps.
- Residential 13D variants can grade water-supply branch selection, local authority caveats, riser/backflow/meter pressure-loss reasoning, and stand-alone versus multipurpose layout reasoning separately from commercial NFPA 13 remote-area calculations.

## Multimodal Extension

- Inputs: hydrant test form/photo, PFI statement, sprinkler plan, riser diagram, pump curve, backflow loss graph, AHJ checklist, plan-review comments, water-supply graph, EPANET/WNTR `.inp` model, network map, or municipal water-model excerpt.
- Inputs for property-risk review variants: FM-style checklist, storage photos or commodity schedule, sectional views, seismic bracing drawing, pump-room drawing, fire-pump curve, and underground fire-water-main drawing.
- Inputs for FM code-support report variants: report excerpts, plan/elevation figures, activation-pattern figures, test-condition tables, commodity descriptions, and recommendation text tied to storage-hazard or ESFR/IRAS decisions.
- Inputs for Canadian public-fire-flow variants: building area/construction/exposure schedule, hydrant map, public/private hydrant maintenance evidence, water-supply reliability summary, and required-fire-flow worksheet.
- Inputs for residential 13D variants: house plan, riser detail, household water-main/tap/meter data, backflow device cut sheet, and local authority notes.
- Outputs: annotated plan, extracted remote area, hydraulic summary table, water supply curve, available-versus-operating pressure table, WNTR fire-flow impact table or network plot, plan/calculation reference-point reconciliation, and pump decision memo.
- Interesting checks: OCR from hydrant forms, extracting pipe nodes from drawings, remote-area selection, curve/demand intersection verification, and whether the drawing/calculation packet satisfies AHJ-required fields.

## Meta-Harness Opportunities

- Reconfigure regional/code basis: NFPA, EN 12845, AS 2118, local AHJ.
- Mutate water supply, hazard class, remote area, elevation, pipe network, or pump curve.
- Combine with pump station by passing fire pump selection into pump-duty checks.
- Combine with structural/fire-safety tasks by requiring occupancy and fire strategy consistency.
- Compose review-packet tasks where the meta-harness creates or repairs a missing artifact: flow-test table, water-supply graph, remote-area annotation, calculation sheet, or AHJ response memo.
- Compose WNTR-backed fire-flow tasks where the meta-harness mutates target node, demand, duration, pressure thresholds, demand model, or impacted-population table and verifies both pressure response and result-table consistency.
- Reframe the same physical scenario across review authorities: AHJ permit review, FM/property-risk review, Canadian public-fire-flow assessment, Australian NCC/AS branch review, or residential 13D branch. The meta-harness can mutate the review authority while preserving shared water-supply and layout facts.
